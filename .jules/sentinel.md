## 2026-07-11 - Path Traversal Vulnerability via Untrusted Network Device Hostnames
**Vulnerability:** The codebase generated local backup and log files using `ip` and `hostname` values directly derived from untrusted network device outputs, which created a path traversal vulnerability. If a compromised or malicious network device supplied a hostname like `../../../etc/passwd`, it could lead to arbitrary file writes.
**Learning:** Network device outputs (like hostnames or IPs) are effectively external, untrusted user input. They should never be used to construct local file paths without strict sanitization. A simple string variable replacement is insufficient protection.
**Prevention:** Always implement explicit filename sanitization for all external or untrusted inputs before using them in file path construction. The regex allowlist should permit specific safe characters (e.g., `[^a-zA-Z0-9_\-\.]`) to ensure valid data, such as IPv4 addresses, are not malformed while preventing directory traversal attacks.

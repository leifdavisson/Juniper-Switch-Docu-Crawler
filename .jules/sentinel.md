## 2026-07-04 - Unsanitized Hostname in File Operations (Path Traversal)
**Vulnerability:** The hostname parsed from the device's unauthenticated/untrusted configuration (via SSH/Telnet output) was used directly as a substring in the backup filename (`filename_hostname`). If a compromised or malicious switch returned a hostname like `../../../../etc/cron.d/pwned`, the crawler could write files outside the intended backups directory, leading to a Path Traversal vulnerability and potential Remote Code Execution (RCE).
**Learning:** Device responses and parsed metadata (even from standard network queries) must always be treated as untrusted input. Directly concatenating such variables into local file paths without sanitization exposes the host machine to arbitrary file writes.
**Prevention:** Always validate and sanitize all dynamic values before using them in file path constructions, using functions like `re.sub(r'[^a-zA-Z0-9_.-]', '_', input_str)` or standard library path utilities that disallow directory traversal characters (`..`, `/`, `\`).
